1. pjollrig.nvim                                      *pjollrig-pjollrig.nvim*

PJOLLRIG — roughly PYOLL-ri(g), with stress on the first syllable.
Swedish: silly, chatty, or prone to idle chatter; a nod to northern Swedish
"pjoller" (chatter and nonsense).

Formerly manicule.nvim. Commands, Lua modules, Plug maps, highlights and User
events now use pjollrig/Pjollrig. The comment store stays under
stdpath("state")/manicule/ so existing comments remain available.

Persistent review comments for Neovim.

pjollrig.nvim lets you attach notes to lines or ranges in any buffer, keep them
anchored with extmarks as text moves, review them in quickfix, and send them to
a sink such as the clipboard or a running coding-agent surface.

It is meant for local code review and follow-up work: leave comments while
reading code, collect them across files, then resolve them or hand them off as
a review batch.


  Status: alpha.

FEATURES                                     *pjollrig-pjollrig.nvim-features*

- Anchored comments on normal files, unrooted files, scratch buffers,
    terminals, and help buffers.
- Floating popups on commented lines, with optional sticky display.
- Quickfix list for scanning, jumping, editing, and deleting comments.
- Project-scoped and session-scoped persistence.
- Pluggable sinks for sending comments elsewhere.
- Built-in clipboard sink and cmux/WezTerm integrations.
- Native `User` autocmd events for lifecycle hooks.

See ARCHITECTURE.md <./ARCHITECTURE.md> for the deeper implementation notes and
event payloads.


REQUIREMENTS                             *pjollrig-pjollrig.nvim-requirements*

Neovim >= 0.12.

The default project store uses the local SQLite library through LuaJIT FFI.
Most Neovim builds on macOS and Linux can load `libsqlite3` already; run
`:checkhealth pjollrig` to confirm.

Run `:checkhealth pjollrig` after setup to verify the store directory, SQLite
support, Neovim API support, clipboard support, and registered sinks.


INSTALL                                       *pjollrig-pjollrig.nvim-install*

With lazy.nvim <https://github.com/folke/lazy.nvim>

>lua
    {
      "MattiasMTS/pjollrig.nvim",
      event = { "BufReadPost", "BufNewFile" },
      cmd = { "PjollrigAdd", "PjollrigList", "PjollrigNext", "PjollrigPrev", "PjollrigSend" },
      keys = {
        { "<leader>ma", "<Plug>(pjollrig-add)", mode = { "n", "x" }, desc = "Pjollrig: add comment" },
        { "<leader>ml", "<Plug>(pjollrig-list)", desc = "Pjollrig: list comments" },
      },
      opts = {},
    }
<

Usean event trigger because setup registers the autocmds that attach existing
records to loaded buffers.


USAGE                                           *pjollrig-pjollrig.nvim-usage*

>vim
    :PjollrigAdd           " add a comment on the current line or visual range
    :PjollrigList          " open project comments in quickfix
    :PjollrigEdit          " pick a comment to edit, or pass a list position
    :PjollrigDelete        " pick a comment to delete, or pass a list position
    :PjollrigResolve       " pick a comment to mark resolved
    :PjollrigToggle        " hide or restore all comment visuals
    :PjollrigNext [count]  " jump to the next comment in the current buffer
    :PjollrigPrev [count]  " jump to the previous comment in the current buffer
    :PjollrigSend [sink]   " send comments to a sink
<

`:PjollrigAdd` opens a small markdown buffer in insert mode. Press `<CR>` to
insert a newline, `<Esc>` then `<CR>` to submit, or `q` in normal mode to
cancel. Moving focus out of the floating editor, including clicking back into
the main buffer, also cancels and discards the draft.

Mouse comments (normal mode): hover a code line to reveal a gutter `+`.
Click for one line, or double-click a code line (no gutter needed).
Comments open on release without a selection preview. Dragging, Escape, or
releasing off the clicked line/button cancels. No drag-to-comment.
On commentable lines double-click commenting replaces
normal-mode double-click word selection; single clicks and ordinary click-drag
selection stay native. Existing editor save/cancel keys are unchanged.

Setup sets `mouse=a` by default (`ui.enable_mouse = true`). Set
`ui.enable_mouse = false` to leave your existing mouse setting untouched;
this does not turn mouse input off or undo an earlier setup. Terminal
mouse-motion support is still required; comment gestures enable
`mousemoveevent`. Ordinary buffers need gutter space
(`:set number` or `:set signcolumn=yes`); all-files review uses its own prefix.
Virtual/removed lines, wrapped continuation rows, and lines whose first column
is horizontally offscreen have no button. Scrolling cancels a pending click.
Set `ui.mouse_comments = false` to disable. Existing global normal-mode mouse mappings disable this feature
with a warning; buffer-local mouse mappings take precedence in their buffers.

Default keymaps:

- `gca` edits the comment at or covering the cursor.
- `gcd` deletes the comment at or covering the cursor.
- `]m` jumps to the next comment in the current buffer.
- `[m` jumps to the previous comment in the current buffer.

Set `vim.g.pjollrig_no_default_keymaps = 1` before loading the plugin to opt
out. Core actions are exposed as `<Plug>` maps so you can choose your own
leader bindings:

>lua
    vim.keymap.set({ "n", "x" }, "<leader>ca", "<Plug>(pjollrig-add)")
    vim.keymap.set("n", "<leader>cl", "<Plug>(pjollrig-list)")
    vim.keymap.set("n", "]c", "<Plug>(pjollrig-next)")
    vim.keymap.set("n", "[c", "<Plug>(pjollrig-prev)")
<


QUICKFIX                                     *pjollrig-pjollrig.nvim-quickfix*

`:PjollrigList` opens a quickfix list titled `pjollrig (...)`.

- `<CR>` jumps to the anchored location.
- `dd` deletes the comment under the cursor.
- `ce` edits the comment under the cursor.
- `u` undoes the last comment deletion (multi-level; repeat to undo more).
- `<C-r>` redoes the last undone deletion (multi-level; a new deletion clears the redo branch).

The list refreshes in place when comments are added, edited, deleted, restored,
or resolved.


CONFIGURATION                           *pjollrig-pjollrig.nvim-configuration*

All keys are optional.

>lua
    require("pjollrig").setup({
      store = {
        dir = vim.fn.stdpath("state") .. "/manicule/",
        format = "mpack", -- session store: "mpack" or "json"
        branch = false,
        persist_unrooted = true,
        canonicalize_symlinks = true,
        root_markers = { ".git", ".hg", "package.json" },
        poll_interval_ms = 750,
      },
      sinks = {
        clipboard = true,
        wezterm = {
          enabled = true,
          auto_submit = false, -- paste only; true sends Enter after the paste
          submit_delay_ms = 120,
          clear_on_success = true, -- default; false keeps comments after a send
        },
        cmux = {
          enabled = true,
          auto_submit = true, -- set false to paste and wait for manual Enter
          submit_delay_ms = 120, -- delay before Enter, lets a large paste settle first
          paste_chunk_bytes = 1024, -- max bytes per paste chunk (large reviews are split to avoid PTY truncation)
          paste_chunk_delay_ms = 80, -- delay between paste chunks so the agent's terminal can drain
          paste_retries = 2, -- re-upload + re-paste attempts per chunk (cmux can silently drop concurrent uploads)
          clear_on_success = true, -- default; false keeps comments after a send
          pre_text = "Optional instructions inserted before the comments.",
          post_text = "Optional follow-up instructions inserted after the comments.",
        },
      },
      ui = {
        width = 72,
        height = 6,
        editor_mode = "insert",
        submit_keys = { "<CR>" },
        cancel_keys = { "q" },
        opacity = 0.0, -- float transparency: 0.0 opaque, 1.0 fully transparent
        sticky = false,
      },
    })
<

`ui.opacity` is fractional float transparency: `0` is opaque, `0.5` is half
transparent, `0.99` is 99% transparent, and `1` is fully transparent.
Pjollrig uses built-in floating lists for send destinations, terminal panes,
comments, PRs, and chat sessions. Use `j`/`k` or the arrow keys to move,
Enter to choose, and Escape or `q` to cancel. Long lists scroll normally.
The send flow still chooses a sink first, then a pane when needed.
`ui.sink_picker` can override the sink list (for example,
`ui = { sink_picker = vim.ui.select }` to use your configured picker).



ALL-FILES REVIEW                                *pjollrig-review-all-files*

    :PjollrigReviewFiles all       " continuous unified diff of all files
    :PjollrigReviewFiles single    " return to per-file diffs
    :PjollrigReviewFiles           " toggle

Configure `review.file_mode = "all"` to use the continuous view by default.
All-files mode renders unified diffs; the per-file `review.diff_mode`
preference is retained. The review buffer is read-only, with file headers,
original old/new line numbers, diff highlighting and comment annotations.

The Files panel scrolls to a file; the Comments panel jumps to a comment.
`]h` / `[h` navigate hunks across files. `za` on a header folds that file.
`gf` opens the working-side source line in another tab for editing. `R`
refreshes the snapshot after edits, preserving the current file/line.
`review.fold_unchanged` and `review.context` control unchanged-code folds.

Add comments using the usual commands. Working-side selections map back to
real source file coordinates. Headers, removed lines and selections crossing
files/removed lines are rejected. Source changes during a prompt invalidate
the selection: refresh and add the comment again. Binary/unreadable files
show placeholders. File and hunk position appear in the window's top bar.


STORAGE                                       *pjollrig-pjollrig.nvim-storage*

Project comments are stored in one SQLite database per project root. The
database uses WAL mode and keeps both a current `records` projection and an
append-only `events` log, so separate Neovim sessions in the same project can
observe each other’s changes without rewriting one whole store file.

Session comments share a `session.<format>` file for unrooted or special
buffers. Stores live under `store.dir`; by default that is:

>vim
    :echo stdpath("state") . "/manicule/"
<

The session file schema is:

>lua
    { version = 1, records = { ... } }
<


SINKS                                           *pjollrig-pjollrig.nvim-sinks*

Sinks receive comment batches from `:PjollrigSend`.

Built-ins:

- `clipboard` copies formatted comments to the `+` register.
- `cmux` sends a markdown review batch to a cmux coding-agent surface and clears
    the sent comments on a successful handoff (`cmux.clear_on_success = false`
    keeps them until you verify fixes).

`cmux.enabled` is boolean. When enabled, the integration registers only when a
cmux workspace and usable cmux executable are available. `cmux.auto_submit`
controls whether Pjollrig presses Enter after pasting the review into the agent
prompt. Set it to `false` if you want to inspect or edit the prompt manually
before submission. `cmux.submit_delay_ms` adds a delay before that Enter key
(default 120ms); values around 100-250ms can help large pasted prompts settle
before submission. Large reviews are automatically split into chunks
(`cmux.paste_chunk_bytes`, default 1024) with a short delay between them
(`cmux.paste_chunk_delay_ms`, default 80ms) to avoid the receiving terminal
dropping the middle of the payload. The cmux server can acknowledge a chunk
upload and still drop it under concurrent load, so each chunk that fails to
paste is re-uploaded and retried (`cmux.paste_retries`, default 2) before the
send aborts. A successful cmux handoff deletes the sent comments; set
`cmux.clear_on_success = false` to keep them. The
bundled text sinks, `clipboard`, `cmux`, and `wezterm`, also accept `pre_text`
and `post_text` strings. These are inserted before and after the formatted
comments while Pjollrig still owns comment IDs and file/range formatting.

WezTerm                                           *pjollrig-wezterm*

`:PjollrigSend wezterm` selects another split in Neovim's current WezTerm tab.
The first send always opens a pane picker showing titles and directories.
The chosen pane is remembered until plugin setup runs again. Later sends
reuse it if it is still in the same tab; otherwise the picker opens again.
`:PjollrigSend wezterm pick` selects a different destination. Lua callers can
use `require("pjollrig").send("wezterm", nil, { pick = true })`.

Registration requires the `wezterm` executable and `WEZTERM_PANE` environment
variable. `sinks.wezterm.command` and `current_pane` override them, and
`sinks.wezterm = false` disables the integration. No WezTerm config is needed.

Delivery leaves focus and the clipboard unchanged. The receiving application
must enable bracketed paste to receive the review as a bracketed paste.
`auto_submit` defaults to false; press Enter in the agent pane after pasting.
When true, Enter follows after `submit_delay_ms` (default 120ms).
`clear_on_success` defaults to true; set it to false so comments remain until
resolved.
`pre_text` and `post_text` wrap the formatted review.

Commands run asynchronously with `timeout_ms` (default 5000) per command.
If a paste fails, inspect the pane before retrying: text may have arrived.
If only submission fails, press Enter manually. Success confirms terminal
delivery, not that the agent has processed the review.

Register a custom sink:

>lua
    require("pjollrig").register_sink({
      name = "mytool",
      label = "My Tool",
      pre_text = "Optional text before formatted comments.",
      post_text = "Optional text after formatted comments.",
      clear_on_success = true, -- default; false keeps comments after a send
      validate = function(ctx)
        if not ctx.token then
          return false, "missing token"
        end
        return true
      end,
      send = function(comments, ctx, cb)
        -- send comments somewhere
        cb(true)
      end,
    })
<

`clear_on_success` defaults to true for every sink, bundled or custom: a
successful send hands the comments off and deletes them locally. Set it to
false on a sink whose delivery is a copy rather than a hand-off. Comments
edited while an asynchronous send is pending stay local; a comment whose
anchor merely moved because the file changed in the meantime is still cleared.


EVENTS                                         *pjollrig-pjollrig.nvim-events*

pjollrig emits native `User` autocmds:

>lua
    vim.api.nvim_create_autocmd("User", {
      pattern = "PjollrigAdded",
      callback = function(ev)
        vim.print(ev.data)
      end,
    })
<

Events: `PjollrigAdded`, `PjollrigEdited`, `PjollrigDeleted`,
`PjollrigRestored`, `PjollrigResolved`, `PjollrigSent`, `PjollrigSynced`,
`PjollrigOrphaned`, `PjollrigRenamed`, and `PjollrigVisibility`.


NOTES                                           *pjollrig-pjollrig.nvim-notes*

- Comments in git diff views are anchored to the working-tree side when the
    reference buffer can be identified.
- Quickfix, prompt, and command-line-window buffers reject new comments.
- Detailed edge cases and data flow are documented in
    ARCHITECTURE.md <./ARCHITECTURE.md>.
